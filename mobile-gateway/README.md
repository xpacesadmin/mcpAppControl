# XSAlpha Mobile Gateway

The gateway is a narrow authorization boundary between the XSAlpha Fleet Console
APK and the existing loopback desktop API. It is not a reverse proxy and has no
route for arbitrary URLs, ADB commands, shell input, proxy edits, account edits,
engagement actions, or workflow JSON.

## Safe defaults

- Production startup refuses wildcard, loopback, public, and non-approved bind
  addresses.
- TLS 1.3 is required. The APK pins the reviewed certificate.
- The desktop origin must be exactly `http://127.0.0.1:<port>/api/v1`.
- Writes are off unless `MOBILE_GATEWAY_WRITES_ENABLED=1` and each action appears in
  `MOBILE_GATEWAY_ALLOWED_ACTIONS`.
- Hermes must be off. Startup rejects `MCP_HERMES_ENABLED=1`, and reads stop if the
  desktop reports Hermes enabled.
- No dependency installation is required; the package uses the Node 22 built-in
  SQLite API.

## Local preparation (no live deployment)

1. Copy `.env.example` values into the owner-approved service environment. Do not
   create a committed `.env` file.
2. Pre-create a gateway data directory restricted to the service account. Set
   `MOBILE_GATEWAY_DB_FILE` to an absolute path in it.
3. Put the desktop bearer token in a service-account-readable file outside the
   repository and set `MOBILE_GATEWAY_DESKTOP_TOKEN_FILE` to that absolute path.
4. Use a reviewed TLS certificate for the VPN hostname/address. Transfer only its
   SHA-256 public certificate pin in the pairing flow; never transfer the private key.
5. Keep `MOBILE_GATEWAY_WRITES_ENABLED=0` for the read-only canary.

`npm test` uses only in-memory databases and fake upstreams. `npm start`, pairing a
real phone, changing VPN/firewall/service configuration, or enabling writes are live
steps and require owner approval.

## Pairing and revocation

Run the pairing CLI locally on the Lab VM after the database path and other reviewed
environment values are configured:

```text
npm run pair:create -- viewer 300
```

The code is single-use and lasts at most 15 minutes. It registers two P-256 public
keys generated by Android Keystore; it never contains the desktop token. For an
emergency revocation of every mobile session:

```text
npm run session:revoke-all
```

## Write enablement

The source includes a fixed declarative action map, asynchronous operation records,
RBAC, confirmations, UUID idempotency keys, rate limits, per-device conflict locks,
route/scope/halt checks, biometric step-up for high-impact actions, and audit events.
It remains inert in the default configuration. Before enabling it, review the canary
evidence and name only the approved actions and packages. There is no like, comment,
follow, raw tap, raw key, shell, terminal, proxy mutation, account mutation, or
arbitrary workflow action.

The stream-ticket route deliberately returns `phase_not_enabled` in the read-only
canary. Do not point it at the existing mirror or publish that mirror to the VPN.
